你是一名资深 Chrome/Edge 浏览器扩展开发工程师。请帮我完整开发一个名为“秋招信息快捷填充助手”的浏览器扩展。

不要只提供示例或伪代码，请生成可以直接加载运行的完整项目，包括全部源代码、目录结构、README、安装步骤和测试页面。所有代码不得使用省略号。

### 一、项目目标

我在秋招网站填写简历时，需要反复输入姓名、手机号、邮箱、学校、专业、学历等信息。

插件需要实现以下工作流程：

1. 用户点击浏览器工具栏中的插件图标。
2. 插件在当前网页右侧显示一个悬浮信息面板。
3. 用户点击网页中的某个表单输入框。
4. 被选中的输入框出现明显但不遮挡内容的高亮边框。
5. 用户点击悬浮面板中的“姓名”“手机号”“邮箱”等按钮。
6. 插件把对应内容写入刚才选中的输入框。
7. 显示“已填入：姓名”等短暂成功提示。
8. 插件只负责填写，不允许自动提交表单。

必须同时兼容最新版 Chrome 和 Chromium 版 Microsoft Edge。优先按照 Chrome Manifest V3 规范实现。

### 二、技术要求

使用以下技术：

* Manifest V3
* 原生 JavaScript、HTML、CSS
* 不使用 React、Vue、Node.js 后端
* 不调用任何网络接口
* 不加载 CDN 或远程脚本
* 所有代码和资源均包含在扩展包中
* 使用 `chrome.*` 扩展 API
* 权限遵循最小化原则

推荐权限：

```json
{
  "permissions": ["activeTab", "scripting", "storage"]
}
```

不要申请 `"<all_urls>"`、浏览历史、Cookie、网络请求等不必要权限。

用户点击扩展图标后，通过后台 service worker 和 `chrome.scripting` 向当前页面注入悬浮面板。相同页面重复点击扩展图标时，应切换面板的显示和隐藏，不能重复注入多个实例。

不要使用普通 action popup 作为主要操作界面，因为用户点击网页输入框时 popup 会关闭。

### 四、悬浮面板设计

悬浮面板应当：

* 默认显示在网页右侧中部。
* 支持拖动。
* 支持折叠、展开和关闭。
* 使用 Shadow DOM 隔离样式，避免被招聘网站 CSS 影响，也避免影响网站样式。
* 面板宽度约为 280～340px。
* 中文界面，简洁清晰。
* 面板层级足够高，但不能遮挡浏览器原生界面。
* 显示当前选中元素的简要信息，例如：

  * `input[name="phone"]`
  * placeholder
  * 附近的 label 文本
* 未选中输入框时，按钮点击后提示“请先点击需要填写的输入框”。
* 点击悬浮面板本身时，不能覆盖或清除之前选中的网页输入框。
* 支持按分组折叠显示按钮。
* 支持按名称搜索信息按钮。

建议分组：

1. 基本信息

   * 姓名
   * 性别
   * 出生日期
   * 手机号
   * 邮箱
   * 身份证号
   * 民族
   * 政治面貌
   * 籍贯
   * 现居住地
   * 详细地址

2. 教育信息

   * 学校
   * 学院
   * 专业
   * 学历
   * 学位
   * 入学时间
   * 毕业时间
   * GPA
   * 专业排名

3. 求职信息

   * 求职方向
   * 期望城市
   * 期望岗位
   * 可入职时间

以上字段只作为默认模板，用户必须能够新增、修改、删除、排序字段和分组。

### 五、个人信息设置页面

实现完整的 `options.html` 设置页面。

用户可以：

* 新增、编辑、删除字段。
* 设置按钮名称、实际填充值、所属分组。
* 设置字段是否属于敏感信息。
* 调整按钮顺序。
* 新建多个信息方案，例如：

  * 中文简历
  * 英文简历
  * 技术岗位
  * 国企岗位
* 切换当前方案。
* 导出全部配置为 JSON。
* 从 JSON 导入配置。
* 清空全部数据，但必须二次确认。
* 恢复默认字段模板。

所有默认字段的值必须为空，不能在源代码中写入真实个人信息。真实信息只能由用户安装后在设置页面自行填写。

### 六、数据存储和安全

使用 `chrome.storage.local`，禁止使用 `chrome.storage.sync`，避免身份证号、手机号等信息同步到云端。

安全要求：

* 不向任何服务器发送数据。
* 不使用统计、埋点或遥测。
* 不在控制台打印个人信息。
* 不把真实信息硬编码进代码。
* 敏感信息在面板中使用掩码显示，例如身份证号显示为 `110***********1234`。
* 用户点击对应按钮时才读取并填入真实值。
* 尽可能通过 `chrome.storage.local.setAccessLevel` 将存储限制在可信扩展上下文。
* content script 不要一次性获取全部真实数据；点击按钮后，再通过消息向 service worker 请求对应字段。
* 明确提示用户：本地存储不等于强加密，不建议保存账号密码、银行卡号、CVV、验证码等信息。
* 永远不填写密码、验证码、银行卡、支付和文件上传控件。
* 提供“一键锁定面板”功能，锁定后不显示或填充任何信息，重新解锁只需当前浏览器会话内的简单 PIN。不要持久化保存明文 PIN。

### 七、目标输入框识别

当悬浮面板处于开启状态时，监听网页中的：

* `focusin`
* `pointerdown`
* `click`

记录用户最近一次选择的可编辑元素。

支持以下标准元素：

* `input[type="text"]`
* `input[type="email"]`
* `input[type="tel"]`
* `input[type="number"]`
* `input[type="date"]`
* `input[type="month"]`
* `input[type="url"]`
* `textarea`
* 原生 `select`
* 带有 `contenteditable="true"` 的元素

忽略以下元素：

* `input[type="password"]`
* `input[type="file"]`
* `input[type="hidden"]`
* 支付、银行卡、CVV、验证码类输入框
* `disabled` 元素
* `readonly` 元素
* 悬浮面板内部元素

如果目标元素不受支持，应显示明确提示，不能静默失败。

### 八、填写逻辑

不能仅使用简单的 `element.value = value`。

对于 `input` 和 `textarea`：

1. 使用对应 HTML 元素原型上的原生 value setter。
2. 设置值后依次触发必要的冒泡事件：

   * `beforeinput`（适用时）
   * `input`
   * `change`
3. 确保 React、Vue、Angular 等框架的受控表单能够感知到变化。
4. 填写后保持目标元素高亮。
5. 触发事件时不能自动提交表单。

对于 `contenteditable`：

* 写入纯文本。
* 触发 `input` 和必要的 change/blur 事件。
* 不允许把用户内容作为 HTML 插入，避免 XSS。

对于原生 `select`：

1. 依次尝试匹配 option 的 `value` 和显示文本。
2. 匹配时去除首尾空格并忽略大小写。
3. 优先精确匹配，不能未经确认选择模糊结果。
4. 选中后触发 `input` 和 `change` 事件。
5. 如果没有匹配项，提示“未找到对应选项”。

对日期字段支持常用格式转换，例如：

* `YYYY-MM-DD`
* `YYYY/MM/DD`
* `YYYY年MM月DD日`
* `YYYY-MM`
* `YYYY年MM月`

用户可以为同一个字段配置多个格式变体，或者在按钮旁选择输出格式。

### 九、撤销和反馈

实现：

* 最近一次填写撤销。
* 填写前记录目标元素原值。
* `Ctrl+Z` 不应被插件破坏。
* 面板提供“撤销上次填写”按钮。
* 成功提示、错误提示和不支持提示。
* 提示在2秒左右自动消失。
* 填写成功后不要自动移动焦点，也不要自动点击下一项。

### 十、兼容性和边界

第一版至少支持普通 HTML 表单，以及 React/Vue 中常见的受控文本输入框。

以下情况如果无法可靠支持，应给出友好提示，并在 README 中明确列为限制：

* 跨域 iframe 中的表单
* closed Shadow DOM
* Canvas 绘制的自定义输入控件
* 网站自定义下拉框、日期选择器和级联选择器
* 验证码
* 文件上传
* 浏览器内部页面，例如 `chrome://`、`edge://`
* Chrome Web Store、Edge Add-ons 等禁止脚本注入的页面

不允许尝试绕过网站安全机制、验证码或反自动化措施。
